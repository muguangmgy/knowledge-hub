## 1. 项目定位

LitePipe 是一套**可复用的异步业务处理骨架**：用户上传文件或提交任务 → 系统落盘并写入元数据 → 发消息异步处理 → 前端订阅进度 → 处理完成后可列表查询与详情查看。用于练手或作为新业务的工程起点。

**目标能力**：

- 跑通「同步接入 + 异步消费 + 进度推送 + 结果可查」全流程
- 覆盖对象存储、关系库元数据、消息队列、缓存进度、统一错误码等常见工程组件
- 模块边界清晰，后续可替换「处理逻辑」而不推翻骨架

**非目标（本规格不做）**：

- 复杂工作流引擎 / BPM
- 多租户权限体系（可后续叠加）
- 性能压测与多活容灾
- 完整运营后台（计费、审核流等）

**学习 / 交付目标**：骨架可启动、依赖可连通、主链路可演示；详细业务规则留给具体项目改写。

## 2. 技术栈

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | Vue3 + Vite + TypeScript + Element Plus + Pinia + Axios + SSE | 单页应用；SSE 收任务进度 |
| 后端 | Spring Boot 3.x + JDK 17 | 单体应用，包名示例 `com.litepipe` |
| 关系库 | MySQL 8 | 任务/文件元数据、处理结果索引 |
| 缓存 / 进度 | Redis | 任务进度 Hash、简单限流 |
| 对象存储 | MinIO（S3 兼容） | 原始文件与产物文件 |
| 消息队列 | RocketMQ | 异步处理任务队列 |
| 文档 / API | SpringDoc OpenAPI | 接口自描述 |

**部署形态**：docker-compose 拉起 MySQL + Redis；MinIO / RocketMQ 若已部署则通过配置连接，不强制进 compose。

## 3. 后端模块拆分

每个模块职责单一、接口清晰，可独立理解与测试。

### 3.1 intake-api（接入层）

接收前端上传或任务创建请求：校验参数 → 原文件写入 MinIO → MySQL 写元记录（`status=PENDING`）→ 发 RocketMQ 消息 `{taskId}` → **立即返回** `taskId`。

### 3.2 worker-consumer（处理消费者）

消费处理消息，编排具体业务步骤（范例：解析 → 转换 → 写回产物）：

- 从 MinIO 拉取原件
- 执行可替换的处理管线（具体算法由项目填充）
- 产物写回 MinIO，结果摘要写 MySQL
- 阶段与进度实时写 Redis；终态回写 MySQL

### 3.3 query（查询层）

任务列表、详情、产物下载链接（预签名或经后端代理）。只读为主，按 `taskId` / 分页条件查询。

### 3.4 progress（进度层）

统一管理任务进度：前端 SSE 订阅 `task/{taskId}/progress`，后端从 Redis 读进度推送；完成后推送终态并关闭流。

### 3.5 common（公共层）

统一响应 `Result`、错误码、全局异常、配置装配（MinIO / MQ Client 等）。不含业务规则。

## 4. 数据流

### 4.1 提交链路

```
前端上传/提交
  → intake-api：MinIO 存原件 + MySQL 建任务(PENDING) + MQ 发 {taskId}
  → 立即返回 taskId
  → 前端 SSE 订阅 progress
```

### 4.2 处理链路

```
worker-consumer 消费 {taskId}
  → Redis 写 stage/progress
  → 拉原件 → 处理管线 → 写产物/摘要
  → MySQL 更新 COMPLETED/FAILED
  → SSE 推送终态
```

### 4.3 查询链路

```
前端列表/详情 → query 读 MySQL（必要时拼 MinIO 下载 URL）→ 返回 VO
```

## 5. 数据模型与存储设计

### 5.1 MySQL（元数据；大文件不进库）

**`lp_task`** — 任务主表

- `id` BIGINT PK
- `title` VARCHAR
- `file_key` VARCHAR（MinIO 原件路径）
- `file_type` VARCHAR
- `size` BIGINT
- `status` VARCHAR（PENDING / RUNNING / COMPLETED / FAILED）
- `result_summary` VARCHAR（短摘要，可选）
- `error_msg` TEXT
- `created_at`, `updated_at` DATETIME

**`lp_task_artifact`** — 产物引用（不存二进制）

- `id` BIGINT PK
- `task_id` BIGINT
- `artifact_key` VARCHAR（MinIO 产物路径）
- `artifact_type` VARCHAR
- `created_at` DATETIME

**`lp_job`** — 消费侧作业状态（可与 task 合并；范例拆开便于重试审计）

- `id` BIGINT PK
- `task_id` BIGINT
- `mq_msg_id` VARCHAR
- `stage` VARCHAR（FETCH / PROCESS / STORE）
- `progress` INT（0–100）
- `retry_count` INT
- `status` VARCHAR
- `error_msg` TEXT
- `created_at`, `updated_at` DATETIME

**关键设计**：二进制只在 MinIO；MySQL 只存 key 与状态。删除任务时按 `task_id` 删元数据并清理对应 MinIO 对象。

### 5.2 Redis

| Key | 类型 | 内容 | TTL |
|-----|------|------|-----|
| `task:progress:{taskId}` | Hash | `stage`、`progress`、`message` | 24h |
| `rate:api:{clientId}` | String/计数 | 接口限流 | 窗口期 |

### 5.3 MinIO

| Bucket | 路径约定 | 内容 |
|--------|----------|------|
| `litepipe-raw` | `{taskId}/{原始文件名}` | 上传原件 |
| `litepipe-out` | `{taskId}/{artifactName}` | 处理产物 |

### 5.4 RocketMQ

| 项 | 约定 |
|----|------|
| Topic | `litepipe_process` |
| Producer group | `litepipe_intake_producer` |
| Consumer group | `litepipe_worker_group` |
| 消息体 | `{"taskId": 123}` |
| 重试 | 业务捕获失败写 FAILED；MQ 重试上限 3，超限进 DLQ |

## 6. 错误处理与可靠性

### 6.1 接入链路

- **上传失败**（MinIO 不可达）：不写 PENDING 任务，或写后立刻标 FAILED 并返回明确错误码；不发 MQ
- **MQ 发送失败**：任务标 FAILED + `error_msg`，支持「仅重发消息」入口（可选）
- **重复提交**：以客户端 `requestId`（可选）或文件 hash 做幂等（项目按需开启）

### 6.2 处理链路

- **消费失败**：更新 `lp_job` / `lp_task` 为 FAILED，依赖 MQ ACK + `retry_count`；超过 3 次进 DLQ，SSE 推失败
- **中途失败重试**：以 `task_id` 为幂等键；重试前清理该任务已写入的产物对象，再重新处理
- **部分步骤可跳过**：非关键步骤失败记日志并降级，不阻塞整任务（由项目定义「关键」）

### 6.3 查询 / 进度

- **SSE 断开**：进度仍以 Redis/MySQL 为准，前端可重连续订
- **任务不存在**：返回明确错误码（如 40401），不空等

### 6.4 通用

- 外部依赖（MinIO / MQ / Redis）：超时 + 有限次重试（如 Spring Retry），不强制上全套熔断组件
- 启动健康检查：关键依赖不可达则启动失败并打错误日志（或降级为 degraded，由项目二选一，推荐启动失败）
- 限流：Redis 计数器限制上传 QPS，防止打满存储与队列

## 7. 测试策略

### 7.1 单元测试（JUnit5 + Mockito）

- 状态机：PENDING → RUNNING → COMPLETED/FAILED 非法跳转被拒绝
- 进度组装：给定 Redis Hash，断言 SSE 推送 DTO 字段正确
- 错误码映射：业务异常 → HTTP 状态与 `Result.code` 一致

### 7.2 集成测试（Testcontainers 或已部署实例）

- MySQL + Redis + MinIO：上传 → 元数据落库 → 对象可下载
- RocketMQ：发送 → 消费 → 任务状态更新
- 不强制每个 PR 起全套容器；可用 profile 区分 `local-it` / CI

### 7.3 端到端冒烟

- 固定小文件走通：返回 `taskId` → 进度到 100 → 详情可查产物
- 标记 `@Tag("e2e")`，CI 默认可不跑

### 7.4 前端测试

- Vitest 覆盖：上传按钮、进度条展示、列表空态
- 不做 Playwright E2E（YAGNI）

### 7.5 明确不测

- 性能压测、多机房故障演练、纯 CRUD 的过度 mock

## 8. API 约定（范例）

| 模块 | 路径前缀 | 说明 |
|------|----------|------|
| 接入 | `/api/intake` | 上传/创建任务 |
| 查询 | `/api/tasks` | 列表、详情、产物链接 |
| 进度 | `/api/tasks/{id}/progress` | SSE |
| 健康 | `/api/health`、`/actuator/health` | 存活与依赖 |

统一响应：

```json
{ "code": 0, "message": "success", "data": { } }
```

错误码示例：`40401` 任务不存在、`50001` 处理失败、`50000` 内部错误。
